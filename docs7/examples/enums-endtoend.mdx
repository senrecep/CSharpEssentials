title: "Enums end-to-end example"
---

An ASP.NET Core API in which one `[StringEnum]` enum and one `[Flags]` enum pass through every layer under a single `EnumConventions` instance: JSON bodies, route, query and header binding, responses, OpenAPI and an EF Core column in PostgreSQL. Background: [CSharpEssentials.Enums](/libraries/enums#across-layers) and the [design document](/design/CSharpEssentials.Enums-DESIGN).

## Run

The app needs PostgreSQL. Start one in Docker and pass the connection string:

```bash
export PGPASSWORD='<choose-a-local-password>'
docker run -d --name shop-postgres -e POSTGRES_PASSWORD="$PGPASSWORD" -p 5432:5432 postgres:17
ConnectionStrings__Shop="Host=localhost;Port=5432;Database=shop;Username=postgres;Password=$PGPASSWORD" \
  dotnet run --project examples/Examples.Enums.EndToEnd
```

`appsettings.json` holds the connection string without a password; give the full string through `ConnectionStrings__Shop` or `dotnet user-secrets`. The app creates the table on startup.

## Files

| File | Shows |
|---|---|
| `OrderStatus.cs` | `[StringEnum]` with `[Description]` texts, an `[EnumAlias]` and an `[EnumFallback]` member |
| `Permissions.cs` | `[Flags]`: a JSON array on the wire, an integer bitmask in the database |
| `Program.cs` | `AddEnumConventions()` and `UseEnumBinding()`; `v1` writes numbers (`WithEnumWireFormat(EnumWireFormat.Number)`), `v2` writes wire names; `AddOpenApi(..., o => o.AddEnumConventions())` |
| `ShopDbContext.cs` | `ConfigureEnumConventions(conventions)`: wire names in a `text` column, check constraints |
| `OrderEndpoints.cs` | Route, query, header and body binding with the same accept rules; a rejected value returns a 400 problem |
| `OrderService.cs` | `Result<Order>` with implicit conversions from `Order` and `Error` |

The sample uses `CSharpEssentials.AspNetCore.OpenApi` (net10.0). A Swashbuckle host references `CSharpEssentials.AspNetCore.Swashbuckle` instead; use one of the two per host.

## Endpoints

Each route exists under `/api/v1` (numbers out) and `/api/v2` (wire names out). Both accept wire names, member names in any casing, aliases and numbers.

| Method | Route | Notes |
|---|---|---|
| GET | `/orders/status/{status}` | `pending_approval`, `PendingApproval`, `approval` (alias) or `1` |
| GET | `/orders?status=&permissions=` | `status` is nullable, so `?status=` binds `null`; `permissions=read,write` or repeated keys |
| GET | `/orders/{id}` | 200, or a 404 problem |
| POST | `/orders` | Body `{ "customer": "ada", "status": "pending_approval", "permissions": ["read", "write"] }`, optional `X-Source-Status` header |
| GET | `/openapi/v1.json`, `/openapi/v2.json` | The two OpenAPI documents |

```bash
curl -i http://localhost:5000/api/v2/orders/status/xyz
# 400: 'xyz' is not a valid OrderStatus. Allowed values: pending, pending_approval, shipped.
```

## Project references

Inside this repository the project uses `ProjectReference`s, including `CSharpEssentials.Enums.Generators` with `OutputItemType="Analyzer"`. Outside it, reference the packages; each brings the enum generator:

```xml
<ItemGroup>
  <PackageReference Include="CSharpEssentials.AspNetCore" Version="9.0.0" />
  <PackageReference Include="CSharpEssentials.AspNetCore.OpenApi" Version="9.0.0" />
  <PackageReference Include="CSharpEssentials.EntityFrameworkCore" Version="9.0.0" />
</ItemGroup>
```
