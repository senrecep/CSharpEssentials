---
title: "CSharpEssentials.Entity"
---

Base classes for DDD entities with audit fields, soft deletion and domain events.

- `EntityBase<TId>`: a typed `Id` (protected setter) plus creation and modification audit fields. `EntityBase` is the same without an ID.
- `SoftDeletableEntityBase<TId>` and `SoftDeletableEntityBase`: add `MarkAsDeleted`, `Restore` and `MarkAsHardDeleted`.
- Domain events: `Raise`, `DomainEvents` and `ClearDomainEvents`, with `[DomainEventTiming]` to choose when the EF Core package publishes each event.
- Interfaces for code that works with any entity: `IEntityBase`, `IEntityBase<TId>`, `ISoftDeletable`, `ICreationAudit`, `IModificationAudit`, `IDomainEventHolder` and `IDomainEvent`, in namespace `CSharpEssentials.Entity.Interfaces`.

Benchmarks of the `EntityBase` domain event list against a hand-written list (read, raise and clear, collect) are in [BENCHMARKS.md](/benchmarks/entity).

## Installation

```bash
dotnet add package CSharpEssentials.Entity
```

Targets `net11.0`, `net10.0`, `net9.0` and `netstandard2.1`. Depends on `CSharpEssentials.Results` and `CSharpEssentials.Time`.

## Usage

### Basic entity

```csharp
using CSharpEssentials.Entity;

public class Product : EntityBase<Guid>
{
    public Product(Guid id) => Id = id;

    public string Name { get; set; } = string.Empty;
}

var product = new Product(Guid.NewGuid()) { Name = "Laptop" };
product.SetCreatedInfo(DateTimeOffset.UtcNow, "system");
product.SetUpdatedInfo(DateTimeOffset.UtcNow, "admin");
```

### Soft-deletable entity

```csharp
public class User : SoftDeletableEntityBase<Guid>
{
    public string Name { get; set; } = string.Empty;
}

var user = new User();
user.MarkAsDeleted(DateTimeOffset.UtcNow, "Admin"); // IsDeleted, DeletedAt, DeletedBy
user.Restore();                                     // clears IsDeleted, DeletedAt, DeletedBy and IsHardDeleted
```

`MarkAsHardDeleted()` sets `IsHardDeleted`, which tells the EF Core `AuditInterceptor` to remove the row instead of converting the delete into a soft delete. The `HardDelete()` extension (on `IEnumerable<T>` where `T : ISoftDeletable`) marks every item. The audit properties (`CreatedAt`, `CreatedBy`, `UpdatedAt`, `UpdatedBy`, `DeletedAt`, `DeletedBy`) have private setters; set them with `SetCreatedInfo`, `SetUpdatedInfo` and `MarkAsDeleted`. `SetCreatedInfo` throws `ArgumentOutOfRangeException` for `DateTimeOffset.MinValue`.

### Domain events

```csharp
using CSharpEssentials.Entity;
using CSharpEssentials.Entity.Interfaces;

public record OrderCreated(Guid OrderId) : IDomainEvent;

public class Order : EntityBase<Guid>
{
    public void Create()
    {
        Id = Guid.NewGuid();
        Raise(new OrderCreated(Id));
    }
}

var order = new Order();
order.Create();

IDomainEvent[] events = [.. order.DomainEvents];
order.ClearDomainEvents();
// dispatch events...
```

`Raise` throws `ArgumentNullException` for `null`. `DomainEvents` is a read-only live view of the entity's events, so reading it does not copy the list. Raising or clearing events while you loop over it throws `InvalidOperationException`; copy it first with `[.. order.DomainEvents]`, as above, when you clear before you dispatch. The EF Core package collects the events of tracked entities and dispatches them; see `CSharpEssentials.EntityFrameworkCore`.

### Event timing

```csharp
// AfterSave (default): published after the save
public record OrderCreatedEvent(Guid OrderId) : IDomainEvent;

// Published before the save; a handler that throws aborts it
[DomainEventTiming(DomainEventTiming.BeforeSave)]
public record OrderValidationEvent(Guid OrderId) : IDomainEvent;
```

The attribute only labels the event; `CSharpEssentials.EntityFrameworkCore` reads it. `BaseDbContext` with `DispatchDomainEventsOnSaveChanges` publishes `AfterSave` events once the save has succeeded. `DomainEventInterceptor` handles them inside `SavingChanges`, still before the database write, so that an outbox can store them in the same save.

## Upgrading to 8.0

- `EntityBase.DomainEvents` returns a read-only live view instead of a new copy on every read. 7.x copied the list each time, so a reference kept before `ClearDomainEvents()` still held the old events, and raising or clearing inside a `foreach` over it was safe. Now a kept reference shows later `Raise` and `ClearDomainEvents` calls, and changing the events during a `foreach` throws `InvalidOperationException`. If you read the events and then clear them, copy them first: `IDomainEvent[] events = [.. entity.DomainEvents];`.
