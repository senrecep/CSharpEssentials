title: "CSharpEssentials.Idempotency"
---

Runs an operation at most once per key and caller, and gives a retry the stored result instead of running it again.
It has no transport of its own: the `Idempotency-Key` middleware of `CSharpEssentials.AspNetCore`, the idempotency
behavior of `CSharpEssentials.Mediator`, message consumers and background jobs all build on it.

The package holds the executor, a message inbox, record stores, scoped record keys, scope resolvers and deterministic
keys built from business ids. No reflection. Targets `net11.0`, `net10.0`, `net9.0` and `netstandard2.1`.

Benchmarks against IdempotentAPI (HTTP replay over the same distributed cache) and hand-written baselines (executor,
inbox, record stores, deterministic keys) are in [BENCHMARKS.md](/benchmarks/idempotency).

## Installation

```bash
dotnet add package CSharpEssentials.Idempotency
```

## Quick start

```csharp Program.cs
// dotnet add package CSharpEssentials.Idempotency
// dotnet add package Microsoft.Extensions.DependencyInjection --version 10.0.1
using System.Text.Json;
using CSharpEssentials.Idempotency;
using Microsoft.Extensions.DependencyInjection;

ServiceCollection services = new();
services.AddIdempotencyExecutor(options =>
    options.AddProfile("payments", profile => profile.Retention = TimeSpan.FromDays(7)));

await using ServiceProvider provider = services.BuildServiceProvider();
await using AsyncServiceScope scope = provider.CreateAsyncScope();
IIdempotencyExecutor executor = scope.ServiceProvider.GetRequiredService<IIdempotencyExecutor>();

IIdempotencyResultCodec<Receipt> codec = IdempotencyResultCodec.Create<Receipt>(
    receipt => JsonSerializer.SerializeToUtf8Bytes(receipt),
    payload => JsonSerializer.Deserialize<Receipt>(payload.Span)!);
IdempotencyExecutionOptions payments = new() { Profile = "payments" };
IdempotencyRecordKey key = new("payments.capture", IdempotencyScope.Tenant("acme"), "order-42");
int charges = 0;

ValueTask<Receipt> Charge(decimal amount)
{
    charges++;
    return ValueTask.FromResult(new Receipt(Guid.NewGuid(), amount));
}

IdempotencyExecution<Receipt> first = await executor.ExecuteAsync(key, "amount=10", payments, _ => Charge(10m), codec);
IdempotencyExecution<Receipt> retry = await executor.ExecuteAsync(key, "amount=10", payments, _ => Charge(10m), codec);
IdempotencyExecution<Receipt> reused = await executor.ExecuteAsync(key, "amount=99", payments, _ => Charge(99m), codec);

Console.WriteLine($"{first.Status}, {retry.Status}, {reused.Status}");
Console.WriteLine($"same receipt: {first.Value!.Id == retry.Value!.Id}, charges: {charges}");

public sealed record Receipt(Guid Id, decimal Amount);
```

Output:

```text
Executed, Replayed, KeyReused
same receipt: True, charges: 1
```

## How it works

An idempotent call has four parts:

- An `IdempotencyRecordKey`: a namespace (who owns the key space, for example `http` or `payments.capture`), a scope (who owns the key: a user, tenant or client) and the key itself.
- A fingerprint: a string that identifies the content. The same key with another fingerprint is `KeyReused`.
- An `IIdempotencyRecordStore` that reserves the key, then stores the result or releases the key.
- A codec that turns the result into bytes and back, and decides whether to keep it.

The first call reserves the key for a lease, runs the operation and stores its result for the retention. A call with the
same key and fingerprint gets the stored result. A call while the first one runs gets `InFlight`.

## Guarantee modes

| | Lease mode | Transactional mode |
|---|---|---|
| How | A store with a reservation token and a lease: in memory, Redis, any store that passes the contract tests | The record is written in the same database transaction as the business data (`EfCoreIdempotencyRecordStore`, Mediator `InsideTransaction`) |
| Duplicates | A run that outlives its lease, or a crash between the side effect and the record write, lets a retry run again after the lease | None for writes in that database: record and data commit or roll back together |
| Use it for | Most operations, and anywhere without a shared database | Money and credit movement, and anything whose duplicate cannot be repaired |

Calls to external systems are outside your transaction in both modes. Send them the same deterministic key
([Deterministic keys](#deterministic-keys)).

The `Idempotency-Key` middleware is always lease mode: it reserves before the endpoint and completes after it, outside
your handler's transaction. For a transactional guarantee over HTTP, parse the header with
`IdempotencyKeyHeader.TryParse` (`CSharpEssentials.AspNetCore`, the middleware's own normalization, so `"abc"` and
`abc` are one key), pass the key to a Mediator command and run it `InsideTransaction`. The middleware (namespace
`http`) and the behavior (namespace: the request type's full name) never share a record, so both can stay.

## Run an operation once

`IIdempotencyExecutor.ExecuteAsync(key, fingerprint, options, operation, codec, cancellationToken)` is the core API. It
wraps any pipeline: a job runner, a consumer or your own dispatcher. The quick start shows it.

| `IdempotencyExecutionStatus` | Meaning |
|------------------------------|---------|
| `Executed` | The operation ran; `Value` is its result |
| `Replayed` | A result stored for the same key and fingerprint; the operation did not run |
| `InFlight` | Another run holds the key. Retry later with the same key |
| `KeyReused` | The key was used with another fingerprint. Do not retry |

`IdempotencyExecution<T>.HasValue` is `true` for `Executed` and `Replayed`.

- A cancellation before the operation starts releases the key.
- An exception thrown by the operation is rethrown and keeps the key in flight until the lease ends, because its side effects are unknown. A retry before then gets `InFlight`.
- A result that cannot be stored is still returned; the key stays in flight until the lease ends.

### Codecs

`IIdempotencyResultCodec<T>` has `Serialize`, `Deserialize` and `Classify`. `IdempotencyResultCodec.Create` builds one
from delegates. `Classify` returns an `IdempotencyResultHandling`:

| Value | Effect |
|-------|--------|
| `Store` (the default without `classify`) | Kept and replayed for `Retention` |
| `StoreAsFailure` | Kept for the shorter `FailureRetention`, then a retry runs again |
| `Release` | Nothing stored, the key is freed. Use it for a failure whose side effects were undone, such as a rolled-back transaction |

```csharp
IIdempotencyResultCodec<Receipt> codec = IdempotencyResultCodec.Create<Receipt>(
    receipt => JsonSerializer.SerializeToUtf8Bytes(receipt),
    payload => JsonSerializer.Deserialize<Receipt>(payload.Span)!,
    receipt => receipt.Declined ? IdempotencyResultHandling.StoreAsFailure : IdempotencyResultHandling.Store);
```

### Options and profiles

| `IdempotencyExecutorOptions` | Default | Meaning |
|------------------------------|---------|---------|
| `Mode` | `Enforce` | `Off`, `Observe` or `Enforce` |
| `Retention` | 24 hours | How long a stored result is replayed |
| `Lease` | 1 minute | How long a running operation blocks its key, and how long the key stays in flight after an exception |
| `FailureRetention` | 10 minutes | Retention of a `StoreAsFailure` result |
| `MaxLease` | 15 minutes | Upper bound for every lease |
| `AddProfile(name, configure)` | | A named set of settings. Names are case-insensitive |
| `ResolveMode(operation)` | | The mode an operation runs in, so a caller can skip computing a fingerprint in `Off` |

An operation passes an `IdempotencyExecutionOptions` with `Profile`, `Mode`, `Retention`, `Lease`, `FailureRetention`
and `StoreKey`. A setting left `null` comes from the profile, then from `IdempotencyExecutorOptions`.

- `StoreKey` sends the operation to a keyed `IIdempotencyRecordStore` registration, for example a database store for payments next to a cache store for the rest.
- `Lease` must be positive and at most `Retention` and `MaxLease`; `FailureRetention` at most `Retention`. `AddIdempotencyExecutor` validates the options and every profile at startup, and the settings of an operation on each call.
- A profile cannot name another profile. A built-in profile named `messaging` (7 days retention) is used by the inbox; registering one with that name replaces it.

`AddIdempotencyExecutor(configure)` registers the options, a scoped `IIdempotencyExecutor`, a scoped
`IdempotencyInbox` and, unless a store is registered, `InMemoryIdempotencyRecordStore`. Calling it again with
`configure` replaces the earlier configuration; without it the configuration is kept. The executor reads
`IOptionsMonitor<IdempotencyExecutorOptions>` on every call, so `Configure` and `Bind` calls apply too, and a
configuration reload takes effect without a restart. A reload that makes the options invalid throws
`OptionsValidationException` on every call until it is fixed.

## Process a message once

`IdempotencyInbox` dedupes message handlers for brokers that have no inbox of their own:

```csharp Program.cs
// dotnet add package CSharpEssentials.Idempotency
// dotnet add package Microsoft.Extensions.DependencyInjection --version 10.0.1
using CSharpEssentials.Idempotency;
using Microsoft.Extensions.DependencyInjection;

ServiceCollection services = new();
services.AddIdempotencyExecutor();

await using ServiceProvider provider = services.BuildServiceProvider();
await using AsyncServiceScope scope = provider.CreateAsyncScope();
IdempotencyInbox inbox = scope.ServiceProvider.GetRequiredService<IdempotencyInbox>();

int receiptsSent = 0;
for (int delivery = 1; delivery <= 2; delivery++)
{
    IdempotencyExecutionStatus status = await inbox.ProcessAsync(
        consumer: "billing.send-receipt",
        messageId: "msg-1001",
        scope: IdempotencyScope.Tenant("acme"),
        handler: _ =>
        {
            receiptsSent++;
            return ValueTask.CompletedTask;
        });
    Console.WriteLine($"delivery {delivery}: {status}");
}

Console.WriteLine($"receipts sent: {receiptsSent}");
```

Output:

```text
delivery 1: Executed
delivery 2: Replayed
receipts sent: 1
```

- `Replayed` means a duplicate: acknowledge it. `InFlight` means another delivery is processing it: redeliver later.
- The namespace is `messaging:{consumer}` and the key `IdempotencyKeys.FromMessage(messageId, consumer)`, so two consumers of one message do not dedupe each other.
- The fingerprint is constant. The message id decides, so a redelivery that serializes differently is still a duplicate.
- The `messaging` profile keeps records for 7 days, long enough for a message resent from a dead-letter queue. Pass `IdempotencyExecutionOptions` to change it.
- A handler that throws keeps the message in flight until the lease ends; a redelivery after that runs it again.
- An overload takes a handler with a result and a codec, and returns `IdempotencyExecution<TResult>`.

## Rollout: Observe → Enforce

| `IdempotencyMode` | Behavior |
|-------------------|----------|
| `Enforce` (default) | A stored result is replayed; an in-flight or reused key stops the operation |
| `Observe` | Keys are reserved and results stored as in `Enforce`, but nothing is blocked. A replay, in-flight key or reused key is logged and counted, and the operation runs |
| `Off` | The operation runs without touching the store |

To add idempotency to an operation that already has callers:

1. Ship it in `Observe`. Callers see no change.
2. Read the [telemetry](#telemetry): `key_reused` shows clients that reuse a key for other content, `in_flight` concurrent duplicates, `replay` how often a retry would be answered from the store, `unscoped` callers without a resolvable scope.
3. Fix what the numbers show, then switch to `Enforce` through configuration.

```csharp Program.cs
// dotnet add package CSharpEssentials.Idempotency
// dotnet add package Microsoft.Extensions.DependencyInjection --version 10.0.1
using System.Diagnostics.Metrics;
using System.Text;
using CSharpEssentials.Idempotency;
using Microsoft.Extensions.DependencyInjection;

ServiceCollection services = new();
services.AddIdempotencyExecutor(options =>
{
    options.Mode = IdempotencyMode.Observe;
    options.AddProfile("payments", profile => profile.Mode = IdempotencyMode.Enforce);
});

Dictionary<string, int> decisions = [];
using MeterListener listener = new();
listener.InstrumentPublished = (instrument, l) =>
{
    if (instrument.Meter.Name == IdempotencyTelemetry.MeterName && instrument.Name == IdempotencyTelemetry.DecisionsInstrumentName)
        l.EnableMeasurementEvents(instrument);
};
listener.SetMeasurementEventCallback<long>((_, value, tags, _) =>
{
    foreach (KeyValuePair<string, object?> tag in tags)
    {
        if (tag.Key == "decision")
            decisions[(string)tag.Value!] = decisions.GetValueOrDefault((string)tag.Value!) + (int)value;
    }
});
listener.Start();

await using ServiceProvider provider = services.BuildServiceProvider();
await using AsyncServiceScope scope = provider.CreateAsyncScope();
IIdempotencyExecutor executor = scope.ServiceProvider.GetRequiredService<IIdempotencyExecutor>();
IIdempotencyResultCodec<string> codec = IdempotencyResultCodec.Create<string>(
    value => Encoding.UTF8.GetBytes(value),
    payload => Encoding.UTF8.GetString(payload.Span));
IdempotencyRecordKey key = new("reports.build", IdempotencyScope.Global, "daily-2026-11-28");

int builds = 0;
for (int run = 1; run <= 2; run++)
{
    IdempotencyExecution<string> result = await executor.ExecuteAsync(key, "daily", null, _ =>
    {
        builds++;
        return ValueTask.FromResult("report");
    }, codec);
    Console.WriteLine($"run {run}: {result.Status}");
}

Console.WriteLine($"builds: {builds}, decisions: {string.Join(", ", decisions.OrderBy(d => d.Key).Select(d => $"{d.Key}={d.Value}"))}");
```

Output:

```text
run 1: Executed
run 2: Executed
builds: 2, decisions: replay=1, reserved=1, stored=1
```

- The mode comes from the operation, else its profile, else `IdempotencyExecutorOptions.Mode`. Bind the options to a reloadable section (`services.Configure<IdempotencyExecutorOptions>(configuration.GetSection("Idempotency:Executor"))`) to switch without a restart. The store is the one registered at startup.
- After the switch to `Enforce`, a result stored in `Observe` is replayed and a key still in flight gets `InFlight`.
- In `Observe` a store that throws while reserving is logged (`Idempotency.Observe.ReserveFailed`) and the operation runs without idempotency, unless the caller cancelled. In `Enforce` the exception propagates.
- The HTTP middleware has its own switch, `IdempotencyOptions.Mode`. The Mediator behavior and the inbox use this one.
- `Observe` measures duplicates; it does not prevent them. Keep it short for operations that move money.

### Transactions in Observe

`Observe` records are real records. With an `ITransactionalIdempotencyRecordStore` (the EF Core store) the executor
and the HTTP middleware reserve through the store's `Detached` view, on a connection of its own, so the reservation
never waits for or fails the business transaction. A result to store releases that reservation and is written through
the store itself, inside the business transaction, so it commits or rolls back with the data as in `Enforce`. What
remains:

- A store that cannot join the transaction (in-memory, distributed cache, Redis) writes the result before the commit when the transaction wraps the idempotency layer, in both modes. If the commit then fails, a retry replays a result for work that never committed. Use the EF Core store, or put the idempotency layer outside the transaction.
- Between the detached release and the write in the transaction, the key is absent for one round trip. A duplicate arriving then is reserved: counted `reserved` instead of `in_flight` in `Observe`, and run on an instance that already runs `Enforce`.
- From that write until the commit, a reservation of the same key waits for the transaction. In `Observe` this can be a deadlock the database cannot see (across the caller's two connections); only the command timeout ends it, and the request then runs without idempotency (`Idempotency.Observe.ReserveFailed`).
- A database error on that write is rolled back to a savepoint, so the business data commits without the record. On PostgreSQL under an isolation level stricter than `READ COMMITTED` (`TransactionScope` defaults to `Serializable`) the write always fails this way, so `Observe` records nothing; run at `READ COMMITTED`, which the store needs anyway. On other providers an error that aborts an ambient `TransactionScope` takes the business data with it.
- On SQL Server a savepoint cannot save a doomed transaction: with `XACT_ABORT ON`, or under `SNAPSHOT` after an update conflict (error 3960), the failed write loses the business data too. Keep `XACT_ABORT` off and avoid `SNAPSHOT` for transactions that run `Observe`, or use `Enforce`.
- If the detached release fails and the commit then fails, the row stays in flight, and after the switch to `Enforce` a retry gets `InFlight` (409) until the lease ends.

## Lease and retry budget

A lease is how long a key stays in flight when nobody settles it: after a crash, an exception, a client abort or a
503/504. A retry gets `InFlight` until the lease ends and then runs once more. Pick it by one rule:

> lease ≥ max(the server's request timeout, the client's total retry budget)

A shorter lease lets a retry start a second run while the first is still working, or lets the client's last attempt
run twice. The defaults are 1 minute (`IdempotencyExecutorOptions.Lease`, `IdempotencyOptions.InFlightTimeout`) and
at most 15 minutes (`MaxLease`, `MaxInFlightTimeout`); a lease may not exceed its retention. The HTTP client retries an
`InFlight` answer after its `Retry-After` (at most `IdempotentRetryOptions.MaxRetryAfter`, 30 seconds by default), so
a long operation needs a client that retries for as long as the lease, or polls for the result.

Set a longer lease per operation or profile, not globally. The reservation token keeps a request that outlived its
lease from overwriting the entry of the retry that took over, but its side effects have already happened.

## Use the store directly

```csharp Program.cs
// dotnet add package CSharpEssentials.Idempotency
using System.Text;
using CSharpEssentials.Idempotency;

InMemoryIdempotencyRecordStore store = new();
IdempotencyRecordKey key = new("imports", IdempotencyScope.Global, IdempotencyKeys.For("import", "file-9"));
TimeSpan lease = TimeSpan.FromMinutes(1);

IdempotencyRecordReservation reservation = await store.TryReserveAsync(key, "sha256-abc", lease);
Console.WriteLine($"reserve: {reservation.Status}");
Console.WriteLine($"reserve again: {(await store.TryReserveAsync(key, "sha256-abc", lease)).Status}");

await store.CompleteAsync(key, reservation.Token!, "sha256-abc", Encoding.UTF8.GetBytes("12 rows"), TimeSpan.FromDays(1));
IdempotencyRecordReservation completed = await store.TryReserveAsync(key, "sha256-abc", lease);
Console.WriteLine($"after complete: {completed.Status}, payload: {Encoding.UTF8.GetString(completed.Payload!.Value.Span)}");
Console.WriteLine($"other content: {(await store.TryReserveAsync(key, "sha256-def", lease)).Status}");

IdempotencyRecordKey other = new("imports", IdempotencyScope.Global, "file-10");
IdempotencyRecordReservation undone = await store.TryReserveAsync(other, "x", lease);
Console.WriteLine($"release: {await store.ReleaseAsync(other, undone.Token!)}, reserve after release: {(await store.TryReserveAsync(other, "x", lease)).Status}");
```

Output:

```text
reserve: Reserved
reserve again: InFlight
after complete: Completed, payload: 12 rows
other content: FingerprintMismatch
release: True, reserve after release: Reserved
```

| `IdempotencyReservationStatus` | Meaning |
|--------------------------------|---------|
| `Reserved` | The key is yours; `Token` is set |
| `InFlight` | Another reservation with the same fingerprint holds the key |
| `Completed` | Done with the same fingerprint; `Payload` holds the stored bytes |
| `FingerprintMismatch` | The key is in flight or done for other content |

`CompleteAsync` and `ReleaseAsync` change the entry only while it carries your token. `ReleaseAsync` frees an in-flight
key when its work was undone; it never removes a completed one.

## Deterministic keys

A caller that is a handler rather than a person has no random key to retry with: a random key would be new on every
redelivery. Build the key from business ids instead, and send the same key downstream.

```csharp Program.cs
// dotnet add package CSharpEssentials.Idempotency
using CSharpEssentials.Idempotency;

Console.WriteLine(IdempotencyKeys.For("refund", "order-42", "refund-1"));
Console.WriteLine(IdempotencyKeys.FromMessage("msg-1001", "billing.send-receipt"));
Console.WriteLine(IdempotencyKeys.ToUuidV5("refund", "order-42", "refund-1"));
Console.WriteLine(IdempotencyKeys.For("refund", "sipariş-42"));
Console.WriteLine(IdempotencyKeys.IsValid("a b"));
```

Output:

```text
6:refund|8:order-42|8:refund-1
7:message|20:billing.send-receipt|8:msg-1001
cea8249b-90bc-5e43-8e3e-311d3992e950
h:NpVl2HjGDCXj-pIDbCy_9rS-JkOL9v1ooYN9Yhoqwy8
False
```

- Each part is written as `{utf8ByteLength}:{value}` and the parts are joined with `|`, so `("a", "bc")` and `("ab", "c")` differ.
- When that string has a character outside printable ASCII (or `"` or `\`) or is longer than 255 characters (`MaxKeyLength`), the key is `h:` plus the unpadded base64url SHA-256 of it. [`tests/vectors/idempotency-key-vectors.json`](https://github.com/senrecep/CSharpEssentials/blob/main/tests/vectors/idempotency-key-vectors.json) pins the format.
- `FromMessage(messageId, consumer)` is `For("message", consumer, messageId)`. Note the argument order.
- `ToUuidV5` gives an RFC 9562 UUIDv5 of the same canonical string in the namespace `9c8fbd17-da5f-4f32-a4bf-651721368d5e` (`UuidNamespace`), for providers that require a UUID.
- `IsValid(key, maxLength)` checks the key rules: 1 to 255 printable ASCII characters other than space, `"` and `\`.
- A part with a lone surrogate throws `ArgumentException`.

The same key then makes the side effect single end to end: the inbox drops the duplicate message, the command drops a
second event for the same order, and the payment provider drops a repeated call.

```csharp
string key = IdempotencyKeys.For("capture", orderId.ToString());
request.SetIdempotencyKey(key); // HttpRequestMessage, CSharpEssentials.Http
```

### Calling an idempotent endpoint

The client side is in `CSharpEssentials.Http`: `request.SetIdempotencyKey(key)` or
`HttpRequestBuilder.WithIdempotencyKey(key)` attaches one key per logical call, and
`RetryUnsafeMethodsOnlyWithIdempotencyKey()` retries a keyed POST or PATCH with that key on a missing response, 408,
429, 503, 504 and `409 Idempotency.InFlight`, never on a replayed response or a `KeyReused`, `KeyInvalid`,
`KeyMissing` or `ScopeRequired` error. See
[Idempotency keys and safe retries](https://github.com/senrecep/CSharpEssentials/blob/main/CSharpEssentials.Http/Readme.MD#idempotency-keys-and-safe-retries).

## Scopes and machine callers

A scope is part of the key, so a key only means something to its owner: `order-42` from two tenants is two records.

```csharp Program.cs
// dotnet add package CSharpEssentials.Idempotency
using System.Security.Claims;
using CSharpEssentials.Idempotency;

ClaimsPrincipal user = new(new ClaimsIdentity([new Claim("sub", "u-7"), new Claim("tenant_id", "acme")], "jwt"));
ClaimsPrincipal machine = new(new ClaimsIdentity([new Claim("client_id", "billing-service")], "jwt"));
ClaimsPrincipal anonymous = new(new ClaimsIdentity());

Console.WriteLine(IdempotencyScopes.User.Resolve(user));
Console.WriteLine(IdempotencyScopes.UserAndTenant("tenant_id").Resolve(user));
Console.WriteLine(IdempotencyScopes.Client.Resolve(machine));
Console.WriteLine(IdempotencyScopes.Custom("account", p => p?.FindFirst("tenant_id")?.Value).Resolve(user));
Console.WriteLine(IdempotencyScopes.User.Resolve(machine)?.ToString() ?? "unresolved");
Console.WriteLine(IdempotencyScopes.User.Resolve(anonymous)?.ToString() ?? "unresolved");

IdempotencyRecordKey key = new("http", IdempotencyScope.Tenant("acme"), "order-42");
Console.WriteLine(key.ToStorageKey());
Console.WriteLine(new IdempotencyRecordKey("http", IdempotencyScope.Global, "order-42").ToStorageKey());
```

Output:

```text
user:u-7
11:tenant:acme/user:u-7
client:billing-service
account:acme
unresolved
unresolved
idem:v3:4:http|11:tenant:acme|8:order-42
idem:v3:4:http|6:global|8:order-42
```

| Resolver (`IdempotencyScopes`) | Scope | Reads |
|--------------------------------|-------|-------|
| `User` | `user:{id}` | `ClaimTypes.NameIdentifier`, then `sub` |
| `Client` | `client:{id}` | `client_id`, then `azp` |
| `Tenant(claimType)` | `tenant:{id}` | The given claim |
| `UserAndTenant(tenantClaimType)` | `{n}:tenant:{tenantId}/user:{userId}` | Both; `{n}` is the UTF-8 length of the tenant part |
| `Custom(kind, resolve)` | `{kind}:{value}` | Your function |
| `Global` | `global` | Nothing; every caller shares the key space |

- The claim-based resolvers return `null` for an anonymous principal or a missing claim. The caller decides what that means; it is never treated as global.
- `IdempotencyScope` is built only by its factories: `User(id)`, `Tenant(id)`, `Client(id)`, `UserAndTenant(userId, tenantId)`, `Custom(kind, value)` and `Global` (also `default`). Each scope starts with its kind, so `Tenant("user:42")` never equals `User("42")`.
- `Custom` rejects a kind that is empty, contains `:` or `/`, is all digits or is a built-in kind (`user`, `tenant`, `client`, `global`, any casing).
- The factories and the `IdempotencyRecordKey` constructor throw `ArgumentException` for a value with an unpaired surrogate. A `null` or `Global` scope gives a global key (`IsGlobal`).
- `ToStorageKey(prefix)` gives `idem:v3:{n}:{namespace}|{n}:{scope}|{n}:{key}` with UTF-8 byte lengths (`DefaultPrefix` is `idem:v3:`), so two different keys never share a storage key.
- `IIdempotencyScopeAccessor.Principal` gives a pipeline without its own request context the current caller. `CSharpEssentials.AspNetCore` registers one that reads `HttpContext.User`.

A machine caller with client credentials has no user claim. Use `IdempotencyScopes.Client` for it, or `UserAndTenant`
or `Custom` when the owner is a pair. When no scope resolves, `UnscopedKeyBehavior` decides, and the layers differ:

| Layer | Default | Keyed request without a scope |
|---|---|---|
| HTTP middleware | `Skip` | Runs without idempotency; logs `Idempotency.UnscopedKeySkipped` |
| Mediator behavior | `Reject` | `Idempotency.ScopeRequired` |

`Global` stores the key under `IdempotencyScope.Global`. Over HTTP `ScopeRequired` is 400, `KeyReused` 422 and
`InFlight` 409 with `Retry-After`. Use the same resolver in both layers so a request that reaches an idempotent command
resolves the same scope. See
[Scopes: HTTP and Mediator defaults](https://github.com/senrecep/CSharpEssentials/blob/main/CSharpEssentials.Mediator/Readme.MD#scopes-http-and-mediator-defaults).

## Transactional store for money movement

When the side effect is a write to your own database, give the record the same transaction: the EF Core store with the
Mediator behavior `InsideTransaction` ([EF Core store](#ef-core-store)). One transaction reserves the key, changes the
data and completes the record, so a crash or rollback leaves neither, and two concurrent requests for one key serialize
on the primary key. A duplicate waits for the first commit.

```csharp
public sealed record CapturePaymentCommand(Guid OrderId, string IdempotencyKey, decimal Amount)
    : ICommand<Result<Receipt>>, ITransactionalRequest, IIdempotentRequest;
```

- A failed `Result` or an exception rolls the transaction back, and the record with it, so a retry runs again.
- Send the payment provider the deterministic key (`IdempotencyKeys.For("capture", orderId.ToString())`): its call is outside your transaction.
- For a hybrid, `AddProfile("payments", p => p.StoreKey = "payments")` with `AddEfCoreIdempotencyRecordStore<AppDbContext>("payments")` sends only that profile to the database.
- Over HTTP the middleware can stay in front for the `Idempotency-Key` contract; the command's record is what keeps the data single.

## Webhook dedupe

Providers deliver at least once and send no `Idempotency-Key`; their event id is the identity. Dedupe it with the
Mediator behavior and the EF Core store: verify the signature over the raw body, then send the command.

```csharp
public sealed record PaymentEventCommand(string AccountId, string EventId, string Payload)
    : ICommand<Result>, ITransactionalRequest, IIdempotentRequest
{
    public string IdempotencyKey => IdempotencyKeys.FromMessage(EventId, "payments-webhook");

    IdempotencyScope? IIdempotentRequest.IdempotencyScope => IdempotencyScope.Custom("account", AccountId);

    string? IIdempotentRequest.IdempotencyFingerprint => "event";
}
```

- Verify the HMAC over the exact bytes the provider sent before you trust the event id. An unverified id must never be claimed, or a forged request turns the real delivery into a duplicate. The [end-to-end example](https://github.com/senrecep/CSharpEssentials/blob/main/examples/Examples.Idempotency.EndToEnd/App/WebhookSignature.cs) has the check, with `CryptographicOperations.FixedTimeEquals`.
- The scope comes from the command, because a webhook has no principal.
- The fingerprint is constant, so the same event serialized differently is a duplicate, never `KeyReused`.
- A duplicate returns the stored success, so the provider stops sending it.
- A failure rolls back and releases the key. Return it as a 5xx (`result.ToProblemResult(statusCode: 500)`) so the provider redelivers; many providers treat a 4xx as final.
- Keep the retention longer than the provider's redelivery window.

## Stores

| Store | Guarantee |
|---|---|
| `InMemoryIdempotencyRecordStore` | Atomic within one process. Expired entries are removed on access and by a sweep at most once a minute. Takes an optional `TimeProvider` |
| `DistributedCacheIdempotencyRecordStore` | Any `IDistributedCache`. Best-effort, not atomic: for one instance or development. Optional key prefix (`KeyPrefix`). An entry it cannot read is treated as absent |
| `EfCoreIdempotencyRecordStore<TContext>` (`CSharpEssentials.EntityFrameworkCore`) | Atomic across instances through a primary key in your `DbContext`. Writes in the context's transaction (`ITransactionalIdempotencyRecordStore`) |

For strict guarantees across instances use the EF Core store or a store with an atomic reserve (Redis `SET NX`, a
unique index), and run the `CSharpEssentials.Idempotency.Testing` contract tests against it.

A store must compare namespace, scope and key ordinally: case-sensitive, trailing spaces significant. A SQL unique index
on text columns can get both wrong: a case-insensitive collation merges `Tenant("ABC")` and `Tenant("abc")`, and a PAD
SPACE collation (every SQL Server collation, `_BIN2` included, and MySQL `utf8mb4_bin`) merges `"abc"` and `"abc "`,
so one scope could replay another's response. Key a SQL store by a fixed-length hash of `ToStorageKey()` in a binary
column, as the EF Core store does; on SQL Server this is the only safe way. Elsewhere a binary NO PAD collation also
works: PostgreSQL `text` or `varchar` (never `char(n)`), MySQL `utf8mb4_0900_bin`, MariaDB `utf8mb4_nopad_bin`.

### Best-effort stores across multiple instances

`DistributedCacheIdempotencyRecordStore` reads the key and then writes it; `IDistributedCache` has no set-if-absent.
Two instances that see a free key at the same moment both reserve it and both run the operation. The later write wins,
so the other instance's `CompleteAsync` returns `false` after its side effect already happened. A completed entry is
not affected: once it exists, every reader replays it.

Use it for one instance, for development, or where a rare duplicate is harmless. Override `IsReservationAtomic` to
`false` in the contract tests of a store you accept as best-effort.

### EF Core store

```csharp
protected override void OnModelCreating(ModelBuilder modelBuilder) =>
    modelBuilder.AddIdempotencyRecords(Database.ProviderName);

services.AddEfCoreTransactionRunner<AppDbContext>();
services.AddMediatorTransactionRunnerBehavior();
services.AddMediatorIdempotencyBehavior(o => o.Placement = IdempotencyPlacement.InsideTransaction);
services.AddEfCoreIdempotencyRecordStore<AppDbContext>();
```

- A request whose transaction rolls back leaves no record, so a redelivered webhook or message runs again. A duplicate that arrives while the first runs waits for its commit and replays its response.
- Records are keyed by `KeyHash`, the SHA-256 of the storage key in a `binary(32)` column, so the collation rule above holds. The readable columns get the binary collation of a known provider; `KeyCollation` overrides it.
- The store needs `READ COMMITTED`. Expired rows count as absent; `PurgeExpiredAsync` deletes them.
- `AddEfCoreIdempotencyRecordStore<AppDbContext>("payments")` registers a keyed store for profiles with `StoreKey = "payments"`.

The [EF Core Readme](https://github.com/senrecep/CSharpEssentials/blob/main/CSharpEssentials.EntityFrameworkCore/Readme.MD#idempotency-records)
has the details and a purge service.

## External stores

There is no Redis or DynamoDB package. You implement `IIdempotencyRecordStore` in your application and prove it with
the contract tests. A store must:

- Make `TryReserveAsync` one atomic operation: of concurrent calls for a free or expired key, exactly one gets `Reserved`. A live entry with another fingerprint returns `FingerprintMismatch`, in flight or completed.
- Make `CompleteAsync` and `ReleaseAsync` compare-and-set on the token. `CompleteAsync` also succeeds when the entry is gone (lease expired, nobody took over); `ReleaseAsync` never removes a completed entry.
- Apply the lease to the in-flight entry and the retention to the completed one, using the durations it is given.
- Build the storage key with `key.ToStorageKey(prefix)` and compare it ordinally.
- Treat the payload as opaque bytes that may be empty, and mark completion separately.
- Throw `ArgumentNullException` for a `null` key, `ArgumentException` for an empty fingerprint or token, and `ArgumentOutOfRangeException` for a lease or retention that is not positive.

### Redis

[`examples/Examples.Idempotency.Redis`](https://github.com/senrecep/CSharpEssentials/tree/main/examples/Examples.Idempotency.Redis)
has a reference store on `StackExchange.Redis` that CI runs against every contract scenario. Each operation is one Lua
script on one key (atomic, works on Redis Cluster). An entry is a hash with `t` (token), `f` (fingerprint) and, once
completed, `p` (payload); lease and retention are `PEXPIRE` TTLs.

- Reserve: when the key is absent, write `t` and `f` and set `PEXPIRE lease`. Otherwise return `FingerprintMismatch` for another `f`, `Completed` with `p` when `p` exists, else `InFlight`.
- Complete: when the key is absent, or `t` matches and `p` does not exist, write `t`, `f` and `p` and set `PEXPIRE retention`.
- Release: when `t` matches and `p` does not exist, `DEL`.

Register it for HTTP with `builder.Services.AddIdempotency(o => o.UseStore<RedisIdempotencyRecordStore>(ServiceLifetime.Singleton))`.
For the executor, the inbox or the Mediator behavior, register it before `AddIdempotencyExecutor`, which keeps an
existing store: `builder.Services.AddSingleton<IIdempotencyRecordStore, RedisIdempotencyRecordStore>()`. For one
profile only, register it as a keyed store and name the key in the profile's `StoreKey`.

### DynamoDB

Use one item per `ToStorageKey()` partition key with `token`, `fingerprint`, `payload` and `expiresAt`, and conditional
writes. DynamoDB TTL deletes late, so expiry is part of every condition.

- Reserve: `PutItem` with `attribute_not_exists(pk) OR expiresAt <= :now`. On `ConditionalCheckFailedException`, read the item (`ReturnValuesOnConditionCheckFailure = ALL_OLD`) and return `FingerprintMismatch`, `Completed` or `InFlight`.
- Complete: `PutItem` with `attribute_not_exists(pk) OR (#token = :token AND attribute_not_exists(payload))`, `expiresAt` set to now plus the retention.
- Release: `DeleteItem` with `#token = :token AND attribute_not_exists(payload)`.
