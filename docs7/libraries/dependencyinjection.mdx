---
title: "CSharpEssentials.DependencyInjection"
---

Registers services in `Microsoft.Extensions.DependencyInjection` from attributes on the classes, and decorates registrations, keyed or not. A source generator writes the registration code at compile time, so startup scans nothing and the app can publish as Native AOT.

Use it in place of hand-written `AddScoped` lists or Scrutor assembly scanning.

## Installation

```bash
dotnet add package CSharpEssentials.DependencyInjection
```

Target frameworks: `net11.0`, `net10.0`, `net9.0`, `net8.0`, `netstandard2.1`. The generic attributes (`[RegisterScoped<TService>]`, `[Decorates<TService>]`) need `net7.0` or later; on `netstandard2.1` use the `typeof(...)` forms. The source generator, analyzer and code fix ship inside the package.

## Quick start

```csharp Program.cs
// dotnet add package CSharpEssentials.DependencyInjection
// dotnet add package Microsoft.Extensions.DependencyInjection --version 10.0.1
using CSharpEssentials.DependencyInjection;
using Microsoft.Extensions.DependencyInjection;

var services = new ServiceCollection();
services.AddAllServices();

using ServiceProvider provider = services.BuildServiceProvider();
using IServiceScope scope = provider.CreateScope();

IOrderService orders = scope.ServiceProvider.GetRequiredService<IOrderService>();
Console.WriteLine(orders.Place("book"));
Console.WriteLine(orders.GetType().Name);

public interface IClock
{
    DateTime UtcNow { get; }
}

[RegisterSingleton]
public sealed class Clock : IClock
{
    public DateTime UtcNow => new(2026, 1, 1, 0, 0, 0, DateTimeKind.Utc);
}

public interface IOrderService
{
    string Place(string item);
}

[RegisterScoped]
public sealed class OrderService(IClock clock) : IOrderService
{
    public string Place(string item) => $"{item} ordered at {clock.UtcNow:O}";
}

[Decorates<IOrderService>]
public sealed class LoggingOrderService(IOrderService inner) : IOrderService
{
    public string Place(string item)
    {
        Console.WriteLine($"placing {item}");
        return inner.Place(item);
    }
}
```

Output:

```text
placing book
book ordered at 2026-01-01T00:00:00.0000000Z
LoggingOrderService
```

`Clock` registers as `IClock` and `OrderService` as `IOrderService` by name. `LoggingOrderService` wraps every `IOrderService` registration. `AddAllServices()` is generated in application projects; libraries get a per-assembly method (see [Generated registry](#generated-registry)).

## Registering services

Three attributes, one per lifetime: `[RegisterSingleton]`, `[RegisterScoped]`, `[RegisterTransient]`. Each has a parameterless form, a `typeof` form and a generic form.

```csharp
[RegisterScoped]                                     // IOrderService, by name
public sealed class OrderService : IOrderService { }

[RegisterSingleton(typeof(ISystemClock))]            // explicit service type
public sealed class UtcClock : ISystemClock { }

[RegisterSingleton<IPaymentGateway>(Key = "card")]   // generic form, keyed
public sealed class CardGateway : IPaymentGateway { }

[RegisterTransient(typeof(IRepository<>))]           // open generic
public sealed class Repository<T> : IRepository<T> { }
```

### Choosing the service type

Without a service type and without `As`, a class registers as the interface it implements whose name is `I{TypeName}` with the same generic arity (`OrderService` as `IOrderService`, `Repository<T>` as `IRepository<T>`). With no such interface it registers as itself, and CSE2003 tells you when the class has other interfaces.

`As` picks the service types instead:

| `As` | Registers |
|---|---|
| `ServiceAs.Self` | the class only |
| `ServiceAs.SelfWithInterfaces` | the class, and each interface as a forward to it, so singleton and scoped instances are shared across interfaces |
| `ServiceAs.ImplementedInterfaces` | each interface with its own registration of the class |

With an explicit service type, `As` adds its types on top of it. Interface expansion skips `IDisposable`, `IAsyncDisposable`, `IEquatable<T>`, `IComparable<T>` and `IEnumerable`.

```csharp Program.cs
// dotnet add package CSharpEssentials.DependencyInjection
// dotnet add package Microsoft.Extensions.DependencyInjection --version 10.0.1
using CSharpEssentials.DependencyInjection;
using Microsoft.Extensions.DependencyInjection;

var services = new ServiceCollection();
services.AddAllServices();
using ServiceProvider provider = services.BuildServiceProvider();

var cache = provider.GetRequiredService<MemoryCache>();
Console.WriteLine(ReferenceEquals(cache, provider.GetRequiredService<IReadCache>()));   // True
Console.WriteLine(ReferenceEquals(cache, provider.GetRequiredService<IWriteCache>()));  // True

public interface IReadCache;

public interface IWriteCache;

[RegisterSingleton(As = ServiceAs.SelfWithInterfaces)]
public sealed class MemoryCache : IReadCache, IWriteCache;
```

### Keys

`Key` takes any attribute constant (string, number, enum, `typeof`). `null`, the default, registers a non-keyed service. Resolve keyed services with `[FromKeyedServices("card")]` or `GetRequiredKeyedService<T>("card")`.

### Strategies

`Strategy` decides what happens when a registration with the same service type and key already exists. Every strategy compares keys too.

| `RegistrationStrategy` | Behavior |
|---|---|
| `Add` (default) | Always appends. |
| `TryAdd` | Appends only if no registration has the same service type and key. |
| `TryAddEnumerable` | Appends only if no registration has the same service type, key and implementation. |
| `Replace` | Removes matching registrations, then appends. |
| `Throw` | Throws `InvalidOperationException` if a matching registration exists. |

With `Add`, a generated registration and a manual `services.AddScoped<IOrderService, OrderService>()` both stay: `GetService<T>()` returns the last one added and `GetServices<T>()` returns both. Use `TryAdd` or `Throw` when one registration is expected.

```csharp Program.cs
// dotnet add package CSharpEssentials.DependencyInjection
// dotnet add package Microsoft.Extensions.DependencyInjection --version 10.0.1
using CSharpEssentials.DependencyInjection;
using Microsoft.Extensions.DependencyInjection;

var services = new ServiceCollection();
services.AddSingleton<IGreeter, TestGreeter>();   // registered first, so TryAdd keeps it
services.AddAllServices();
using ServiceProvider provider = services.BuildServiceProvider();

Console.WriteLine(provider.GetRequiredService<IGreeter>().Greet());                      // test
Console.WriteLine(provider.GetServices<INotifier>().Count());                            // 2
Console.WriteLine(provider.GetRequiredKeyedService<INotifier>("sms").GetType().Name);    // SmsNotifier

public interface IGreeter
{
    string Greet();
}

[RegisterSingleton(Strategy = RegistrationStrategy.TryAdd)]
public sealed class Greeter : IGreeter
{
    public string Greet() => "hello";
}

public sealed class TestGreeter : IGreeter
{
    public string Greet() => "test";
}

public interface INotifier;

[RegisterTransient<INotifier>(Strategy = RegistrationStrategy.TryAddEnumerable)]
public sealed class EmailNotifier : INotifier;

[RegisterTransient<INotifier>(Strategy = RegistrationStrategy.TryAddEnumerable)]
[RegisterTransient<INotifier>(Key = "sms")]
public sealed class SmsNotifier : INotifier;
```

A class may carry several registration attributes, as `SmsNotifier` shows.

### Excluding

`[ExcludeFromRegistration]` on a class keeps it from being registered or applied as a decorator. On an assembly (`[assembly: ExcludeFromRegistration]`) no registry is generated and the reflection fallback skips it.

## Decorating services

### With an attribute

```csharp
[Decorates(typeof(IOrderService), Order = 1)]
public sealed class LoggingOrderService(IOrderService inner, ILogger<LoggingOrderService> logger) : IOrderService { }

[Decorates<IPaymentGateway>(Key = "card")]
public sealed class RetryingGateway(IPaymentGateway inner) : IPaymentGateway { }
```

- `Order`: lower values are applied first and end up innermost. Ties are broken by assembly order, then type name.
- `Key`: decorates the registrations with that key. `null` decorates non-keyed ones.
- The decorator needs exactly one public constructor with exactly one parameter of the decorated type (CSE2004, CSE2005). Other parameters are resolved from the container.
- The attribute may repeat to decorate several services or keys. A decorator is not registered as a service itself.
- Open-generic decorators are not generated (CSE2008). Use `Decorate(Type, Type)` at runtime.

### At runtime

```csharp Program.cs
// dotnet add package CSharpEssentials.DependencyInjection
// dotnet add package Microsoft.Extensions.DependencyInjection --version 10.0.1
using Microsoft.Extensions.DependencyInjection;

var services = new ServiceCollection();
services.AddSingleton<IClock, FixedClock>();
services.AddKeyedSingleton<IClock, FixedClock>("utc");
services.AddScoped<IRepository<Order>, Repository<Order>>();

services.Decorate<IClock, LoggingClock>();                                  // non-keyed only
services.Decorate<IClock, LoggingClock>(serviceKey: "utc");                 // the keyed one
services.Decorate<IClock>((inner, sp) => new OffsetClock(inner, hours: 1)); // factory form
bool decorated = services.TryDecorate<IMissing, MissingDecorator>();        // false, nothing registered
services.Decorate(typeof(IRepository<>), typeof(CachedRepository<>));       // closed registrations

using ServiceProvider provider = services.BuildServiceProvider();
using IServiceScope scope = provider.CreateScope();

Console.WriteLine(provider.GetRequiredService<IClock>().Now().Hour);                  // 13
Console.WriteLine(provider.GetRequiredKeyedService<IClock>("utc").Now().Hour);        // 12
Console.WriteLine(decorated);                                                         // False
Console.WriteLine(scope.ServiceProvider.GetRequiredService<IRepository<Order>>().Describe());

public interface IClock
{
    DateTime Now();
}

public sealed class FixedClock : IClock
{
    public DateTime Now() => new(2026, 1, 1, 12, 0, 0, DateTimeKind.Utc);
}

public sealed class LoggingClock(IClock inner) : IClock
{
    public DateTime Now()
    {
        Console.WriteLine("reading clock");
        return inner.Now();
    }
}

public sealed class OffsetClock(IClock inner, int hours) : IClock
{
    public DateTime Now() => inner.Now().AddHours(hours);
}

public interface IMissing;

public sealed class MissingDecorator(IMissing inner) : IMissing
{
    public IMissing Inner { get; } = inner;
}

public sealed record Order(int Id);

public interface IRepository<T>
{
    string Describe();
}

public sealed class Repository<T> : IRepository<T>
{
    public string Describe() => $"repository of {typeof(T).Name}";
}

public sealed class CachedRepository<T>(IRepository<T> inner) : IRepository<T>
{
    public string Describe() => "cached " + inner.Describe();
}
```

| Method | Behavior |
|---|---|
| `Decorate<TService, TDecorator>(object? serviceKey = null)` | Decorates every registration of `TService` with that key. Throws `InvalidOperationException` when none exists. |
| `TryDecorate<TService, TDecorator>(object? serviceKey = null)` | Same, but returns `false` when none exists. |
| `Decorate<TService>(Func<TService, IServiceProvider, TService> decorator, object? serviceKey = null)` | Builds the decorator with a factory. Throws when none exists. |
| `Decorate(Type serviceType, Type decoratorType)` | Decorates every closed registration of an open generic service type (`IRepository<Order>`) with the decorator closed over the same arguments. Throws when a registration of the open type itself exists (`typeof(IRepository<>)`) or no closed registration matches. Marked `[RequiresUnreferencedCode]` and `[RequiresDynamicCode]`. |

### How decoration works

- Every matching registration is decorated, and the decorator keeps its lifetime and key.
- The original moves to a hidden registration under a private key and a service type other than `T` and `object`, so it never shows up in `GetServices<T>()` or `GetKeyedServices<T>(KeyedService.AnyKey)`.
- The hidden inner of a scoped service is transient: the scope caches the decorator, which resolves one inner.
- The container disposes both the decorator and the original. If decoration fails, the collection is left unchanged.
- Decorator parameters follow container rules: `[ServiceKey]` receives the decorated key, `[FromKeyedServices("k")]` resolves key `k`, `[FromKeyedServices(null)]` the non-keyed registration, and the parameterless `[FromKeyedServices]` (.NET 10) inherits the decorated key.
- An original implementation that injects `[ServiceKey]` cannot be decorated, because its inner registration uses a private key. `Decorate` throws `InvalidOperationException`.

## Generated registry

Each assembly with marked classes gets an `Add{Asm}Services` extension method in the `Microsoft.Extensions.DependencyInjection` namespace. `{Asm}` is the assembly name with non-identifier characters removed and each segment capitalized (`Sample.Billing` gives `AddSampleBillingServices`). It registers the assembly's services, then applies the assembly's decorators.

```csharp
services.AddSampleBillingServices();
services.AddSampleBillingServices(logger);   // optional ILogger: logs duplicate (service type, key) registrations at Debug
```

### AddAllServices

Applications (`Exe` or `WinExe`, not test projects) also get an internal `AddAllServices(ILogger? logger = null)`. It registers the services of every referenced assembly that has a registry, and of the application itself, before it applies any decorator. Decorators of all assemblies are then applied together in ascending `Order`; ties follow assembly order (referenced assemblies by name, the application last), then type name.

`Add{Asm}Services` applies its decorators right away, so a decorator for a service from another assembly needs that registration to exist first, or `Decorate` throws. With per-assembly calls, register dependencies first:

```csharp
services.AddSampleBillingServices();   // registers IPaymentGateway
services.AddSampleAuditServices();     // decorates IPaymentGateway
```

`AddAllServices` has no such ordering requirement. Prefer it in applications.

### Assembly attributes

| Attribute | Effect |
|---|---|
| `[assembly: ServiceRegistryName("Billing")]` | Names the method `AddBillingServices`. |
| `[assembly: GenerateServiceAggregate]` | Generates `AddAllServices()` in a library or test project. |
| `[assembly: DisableServiceAggregate]` | Turns off `AddAllServices()` in an application. |
| `[assembly: ServiceModule(typeof(...))]` | Written by the generator to mark an assembly with a registry. Do not add it yourself. |

### Calling it twice

Registration is idempotent per assembly. A second `Add{Asm}Services` call, or one after `AddAllServices`, does nothing, and `AddAllServices` and `AddServicesFromAssemblies` skip assemblies already registered by any of them. The marker is a singleton descriptor of an internal type: it counts in `services.Count` but is never resolved.

The marker is written only after the assembly's registrations and decorators succeed. A call that threw (for example a `Throw` conflict) leaves the descriptors it already added, and `AddAllServices` marks its assemblies only after all of them succeed. Fix the cause and build a new collection rather than retrying.

### Remaining reflection

Before decorating a registration, the runtime reads the public constructors of the implementation type once per process to reject a type that injects `[ServiceKey]`. The generator skips that read for a non-generic, non-partial type registered by attribute in the decorator's own assembly under the same service type and key. Manual registrations, generic types, partial types and types from other assemblies still get the read.

## Reflection fallback

For assemblies that cannot run the generator, such as plugins loaded at runtime:

```csharp
services.AddServicesFromAssemblies(pluginAssembly);
services.AddServicesFromAssemblies(logger, pluginAssembly);   // warns on unloadable types instead of throwing
```

- Same rules, strategies and decorator ordering as the generated path, with assemblies in the order passed.
- Without a logger, an assembly whose types cannot all be loaded throws `InvalidOperationException`.
- Marked `[RequiresUnreferencedCode]` and `[RequiresDynamicCode]`. Trimming can remove constructors that only the fallback uses; a decorator left without a public constructor then fails with an error that names trimming. `Decorate<TService, TDecorator>()` keeps the decorator constructor through its annotation, so it works in trimmed apps.

## Testing for duplicate registrations

A unit test catches unintended duplicates under the default `Add` strategy. Hidden decorator originals use private keys, so they never count.

```csharp Program.cs
// dotnet add package CSharpEssentials.DependencyInjection
// dotnet add package Microsoft.Extensions.DependencyInjection --version 10.0.1
using CSharpEssentials.DependencyInjection;
using Microsoft.Extensions.DependencyInjection;

var services = new ServiceCollection();
services.AddAllServices();
services.ShouldHaveNoDuplicateRegistrations(allowMultiple: typeof(IChannel));
Console.WriteLine("no duplicates");

public static class ServiceCollectionAssertions
{
    public static void ShouldHaveNoDuplicateRegistrations(this IServiceCollection services, params Type[] allowMultiple)
    {
        List<string> duplicates = services
            .Where(descriptor => !allowMultiple.Contains(descriptor.ServiceType))
            .GroupBy(descriptor => (descriptor.ServiceType, descriptor.ServiceKey))
            .Where(group => group.Count() > 1)
            .Select(group => $"{group.Key.ServiceType} (key: {group.Key.ServiceKey ?? "none"}) registered {group.Count()} times")
            .ToList();

        if (duplicates.Count > 0)
        {
            throw new InvalidOperationException("Duplicate registrations:" + Environment.NewLine + string.Join(Environment.NewLine, duplicates));
        }
    }
}

public interface IChannel;

[RegisterSingleton<IChannel>]
public sealed class EmailChannel : IChannel;

[RegisterSingleton<IChannel>]
public sealed class PushChannel : IChannel;
```

In a test project, call `services.AddMyAppServices()` (the registry of the assembly under test) in a `[Fact]` and assert the same way. Pass service types that are meant to have several implementations as `allowMultiple`.

## Diagnostics

| ID | Severity | Rule |
|---|---|---|
| CSE2001 | Error | The class does not implement the service type. |
| CSE2002 | Error | A `RegistrationStrategy.Throw` registration whose service type and key an earlier registration in the same assembly already registers. Types are registered in metadata name order, so a `Throw` registration that comes first does not fail. |
| CSE2003 | Info | The class has interfaces, but none is named `I{TypeName}`, so it registers as itself. Has a code fix. |
| CSE2004 | Error | The decorator constructor has no parameter of the decorated type, or more than one. |
| CSE2005 | Error | The decorator does not have exactly one public constructor. |
| CSE2006 | Info | Captive dependency: a singleton takes a scoped or transient service, or a scoped one takes a transient, registered by attribute in the same project. Checked for single-constructor classes. Treat it as a bug. |
| CSE2007 | Error | The class cannot be constructed by generated code (abstract, static, file-local, inaccessible, or nested in a generic type). |
| CSE2008 | Warning | Open-generic decorators are not generated. Call `services.Decorate(typeof(IRepository<>), typeof(CachedRepository<>))` at runtime. |
| CSE2009 | Warning | Two referenced assemblies produce the same registry name (`Foo.Api` and `FooApi` both give `FooApiServiceRegistry`). `AddAllServices` skips both; when the own registry shares the name, only the own one is called. Fix with `[assembly: ServiceRegistryName("...")]`. Reported only where the aggregate is generated. |

The CSE2003 code fix offers one action per implemented interface, which adds `typeof(IFoo)` (`typeof(IFoo<>)` for a generic class) to the attribute, and one that adds `As = ServiceAs.Self` to keep the registration and silence the message.

## Migrating from Scrutor

| Scrutor | CSharpEssentials.DependencyInjection |
|---|---|
| `services.Scan(s => s.FromAssemblyOf<T>().AddClasses(...))` | A registration attribute on each class, then `services.Add{Asm}Services()` |
| `.AsMatchingInterface()` | The default `I{TypeName}` rule |
| `.As<IFoo>()` | `[RegisterScoped(typeof(IFoo))]` or `[RegisterScoped<IFoo>]` |
| `.AsSelf()`, `.AsSelfWithInterfaces()`, `.AsImplementedInterfaces()` | `As = ServiceAs.Self`, `SelfWithInterfaces`, `ImplementedInterfaces` |
| `.WithScopedLifetime()` | The attribute name carries the lifetime |
| `RegistrationStrategy.Append`, `Skip`, `Replace()`, `Throw` | `Strategy = RegistrationStrategy.Add`, `TryAdd`, `Replace`, `Throw` |
| `[ServiceDescriptor(typeof(IFoo), ServiceLifetime.Scoped)]` with `.UsingAttributes()` | `[RegisterScoped(typeof(IFoo))]` |
| `services.Decorate<IFoo, FooDecorator>()`, `TryDecorate` | The same calls (keyed too), or `[Decorates(typeof(IFoo))]` |
| `.FromApplicationDependencies()` | `AddAllServices()` |
| Namespace or type filters | `[ExcludeFromRegistration]` |

1. Add attributes to the classes the `Scan` call registered. Build: CSE2003 points at classes whose interfaces do not follow `I{TypeName}`, and the code fix adds the service type.
2. Replace `Scan` with `services.Add{Asm}Services()`, or `AddAllServices()` in the application.
3. Move `Decorate` calls to `[Decorates]` or keep them.
4. Remove Scrutor. Both libraries define `Decorate` and `TryDecorate` in `Microsoft.Extensions.DependencyInjection`, so the calls are ambiguous while both are referenced.

Not supported: registering every class by convention, custom interface-matching predicates, and decorating open-generic registrations (closed registrations work with `Decorate(Type, Type)`).

## Performance

Measured on net10 against Scrutor 7.0.0 and manual registration; full tables in [BENCHMARKS.md](https://github.com/senrecep/CSharpEssentials/blob/main/CSharpEssentials.DependencyInjection/BENCHMARKS.md).

- Cold register + build + resolve takes 26.35 ms for the generated registry, 25.08 ms by hand and 34.53 ms for Scrutor (N = 50; 58.71 / 56.53 / 64.80 ms at N = 500).
- The reflection fallback is slower than Scrutor (35.46 ms) and allocates more.
- Decorated resolve takes 129.7 ns, against 111.0 ns for a hand-written factory and 391.7 ns for Scrutor.
- The generated path publishes with Native AOT without warnings; Scrutor and the reflection fallback crash under AOT (samples without `TrimmerRootAssembly`).

Design-time cost of the generator against Injectio is in [the generator BENCHMARKS.md](https://github.com/senrecep/CSharpEssentials/blob/main/CSharpEssentials.DependencyInjection.Generators/BENCHMARKS.md).
