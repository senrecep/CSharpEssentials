---
title: "CSharpEssentials.Rules"
---

A small rule engine on top of `CSharpEssentials.Results`. A rule is a class, a `Func` or a predicate that returns `Result` or `Result<T>`. You combine rules with And, Or, Linear (stop at the first failure) and If, then evaluate the tree with `RuleEngine`. Use it when business checks need to be reusable and composable instead of nested `if` blocks.

```bash
dotnet add package CSharpEssentials.Rules
```

Targets `net11.0`, `net10.0`, `net9.0` and `netstandard2.1`. Depends on `CSharpEssentials.Results` and `CSharpEssentials.Errors`.

```csharp
using CSharpEssentials.Rules;         // IRule<T>, IAsyncRule<T>, RuleEngine, And/Or/Linear/Next/ToRule
using CSharpEssentials.ResultPattern; // Result, Result<T>
using CSharpEssentials.Errors;        // Error
```

## Quick start

```csharp Program.cs
// dotnet add package CSharpEssentials.Rules
using CSharpEssentials.Errors;
using CSharpEssentials.ResultPattern;
using CSharpEssentials.Rules;

IRule<Applicant> age = new MinimumAgeRule(18);
Func<Applicant, Result> license = a => a.HasLicense
    ? Result.Success()
    : Error.Validation("Applicant.NoLicense", "A driver's license is required.");
IRule<Applicant> country = RuleEngine.FromPredicate<Applicant>(
    a => a.Country is "TR" or "DE",
    a => Error.Forbidden("Applicant.Country", $"Country '{a.Country}' is not supported."));

IRuleBase<Applicant> canRent = new IRuleBase<Applicant>[] { age, license.ToRule(), country }.And();

foreach (Applicant applicant in new[] { new Applicant("Ada", 30, true, "TR"), new Applicant("Bo", 16, false, "TR") })
{
    Result result = RuleEngine.Evaluate(canRent, applicant);
    Console.WriteLine(result.IsSuccess
        ? $"{applicant.Name}: approved"
        : $"{applicant.Name}: {result.FirstError.Description}");
}

internal sealed record Applicant(string Name, int Age, bool HasLicense, string Country);

internal sealed class MinimumAgeRule(int minimum) : IRule<Applicant>
{
    public Result Evaluate(Applicant context, CancellationToken cancellationToken = default) =>
        context.Age >= minimum
            ? Result.Success()
            : Error.Validation("Applicant.Underage", $"Applicant must be at least {minimum}.");
}
```

Output:

```text
Ada: approved
Bo: Applicant must be at least 18.
```

## Writing rules

The snippets below reuse the quick start: `applicant` is an `Applicant`, and `age`, `license` and `country` are the rules defined there. `GrantRule` and `DenyRule` stand for any `IRule<Applicant>` classes.

### As a class

Implement `IRule<TContext>` when the rule needs dependencies, state or a name.

```csharp
public sealed class MinimumAgeRule(int minimum) : IRule<Applicant>
{
    public Result Evaluate(Applicant context, CancellationToken cancellationToken = default) =>
        context.Age >= minimum ? Result.Success() : Error.Validation("Applicant.Underage", "Too young.");
}
```

### As a Func

`RuleEngine.Evaluate`, `RuleEngine.If`, the static `And`/`Or`/`Linear` shortcuts, the `.And()` and `.Or()` extensions on `Func[]` and `.Next()` all accept a `Func<TContext, Result>` (or `Func<TContext, CancellationToken, Result>`) directly. A lambda or a method group works.

```csharp
Func<Applicant, Result> license = a => a.HasLicense ? Result.Success() : Error.Validation("Applicant.NoLicense", "License required.");

Result r1 = RuleEngine.Evaluate(license, applicant);
Result r2 = RuleEngine.Evaluate((Applicant a) => a.Age > 0 ? Result.Success() : Error.Validation("Age", "Invalid age."), applicant);
```

`.ToRule()` turns a `Func` into an `IRule`. You need it to put a `Func` into an `IRuleBase<T>[]` next to class rules, to call the `.Linear()` extension (it has no `Func[]` overload) and to turn an async `Func` into an `IAsyncRule`.

### From a predicate

`FromPredicate` builds a rule from a `bool` check and an error, or an error factory that sees the context.

```csharp
IRule<int> positive = RuleEngine.FromPredicate<int>(x => x > 0, Error.Validation("Value.Negative", "Must be positive."));
IRule<int> inRange = RuleEngine.FromPredicate<int>(
    x => x is >= 1 and <= 100,
    x => Error.Validation("Value.OutOfRange", $"{x} must be between 1 and 100."));
```

`FromPredicateAsync` does the same with a `Func<TContext, Task<bool>>` and returns an `IAsyncRule<TContext>`. The predicate does not receive a cancellation token.

## Combining rules

### And

All rules must pass.

```csharp
IRuleBase<Applicant> all = new IRuleBase<Applicant>[] { age, license.ToRule(), country }.And();
IRuleBase<Applicant> fromFuncs = new Func<Applicant, Result>[] { license, a => Result.Success() }.And();
Result result = RuleEngine.Evaluate(all, applicant);
```

For `Result` rules, `And` stops at the first failure and returns its errors. For `Result<T>` rules, see [Rules that return a value](#rules-that-return-a-value).

### Or

At least one rule must pass. `Or` returns success at the first passing rule. When every rule fails, the result carries the errors of all of them, in order.

```csharp
IRuleBase<Applicant> any = new IRuleBase<Applicant>[] { age, license.ToRule() }.Or();
```

### Linear and Next

`Linear` runs rules in order and stops at the first failure. `a.Next(b)` links two rules the same way. `a.Next(b).Next(c)` appends `c` to the end, so it behaves like `new[] { a, b, c }.Linear()`.

```csharp
IRuleBase<Applicant> chain = new IRule<Applicant>[] { age, country }.Linear();
IRule<Applicant> linked = age.Next(license).Next(country);
```

The `.Linear()` extension exists on `IRule<T>[]` and `IAsyncRule<T>[]`. `Next` accepts another rule or a `Func`.

### Static shortcuts

`RuleEngine.And`, `RuleEngine.Or` and `RuleEngine.Linear` take the array and the context in one call. They accept `IRule<T>[]` and every `Func` shape.

```csharp
Func<Applicant, Result>[] checks = [license, a => a.Age >= 18 ? Result.Success() : Error.Validation("Age", "Too young.")];

Result both = RuleEngine.And(checks, applicant);
Result either = RuleEngine.Or(checks, applicant);
Result inOrder = RuleEngine.Linear(checks, applicant);
```

These shortcuts build the tree on every call. For `RuleEngine.Linear(Func[], ctx)` that costs 1.94 to 2.59 times the prebuilt chain (see [BENCHMARKS.md](https://github.com/senrecep/CSharpEssentials/blob/main/CSharpEssentials.Rules/BENCHMARKS.md)), so on a hot path build the tree once and keep it.

### If

`RuleEngine.If` evaluates a condition and then runs the `success` or the `failure` branch. The condition is a rule, a `Func` or a plain `bool`. The result is the result of the branch that ran.

```csharp
Result fromRule = RuleEngine.If(age, success: new GrantRule(), failure: new DenyRule(), applicant);

Result fromBool = RuleEngine.If(applicant.HasLicense, success: new GrantRule(), failure: new DenyRule(), applicant);

Result fromFuncs = RuleEngine.If(
    (Applicant a) => a.Age >= 18 ? Result.Success() : Error.False,
    success: a => Result.Success(),
    failure: a => Error.Forbidden("Access.Denied", "Access denied."),
    applicant);
```

## Rules that return a value

`IRule<TContext, TResult>` and `Func<TContext, Result<TResult>>` return a value with the outcome. Every combinator has a `Result<T>` version.

```csharp
Func<int, Result<string>>[] graders =
[
    score => score >= 90 ? "A" : Error.Validation("Grade.NotA", "Below 90."),
    score => score >= 80 ? "B" : Error.Validation("Grade.NotB", "Below 80."),
];

Result<string> grade = RuleEngine.Or(graders, 85);   // success, "B"
Result<string> strict = RuleEngine.And(graders, 70); // failure: Grade.NotA and Grade.NotB
```

| Combinator | `Result` rules | `Result<T>` rules |
|---|---|---|
| And | stops at the first failure | runs every child, returns all errors, or the first child's value on success |
| Or | first success wins, else all errors | first success wins with its value, else all errors |
| Linear | stops at the first failure | stops at the first failure, returns the last value |

## Async rules

Implement `IAsyncRule<TContext>`, use `FromPredicateAsync`, or convert a `Func<TContext, CancellationToken, ValueTask<Result>>` with `.ToRule()`. Then await `RuleEngine.EvaluateAsync`.

```csharp Program.cs
// dotnet add package CSharpEssentials.Rules
using CSharpEssentials.Errors;
using CSharpEssentials.ResultPattern;
using CSharpEssentials.Rules;

HashSet<string> taken = ["admin", "root"];

IAsyncRule<string> notEmpty = ((Func<string, CancellationToken, ValueTask<Result>>)((name, ct) =>
    ValueTask.FromResult(name.Length > 0 ? Result.Success() : Error.Validation("Name.Empty", "Name is required.")))).ToRule();

IAsyncRule<string> unique = RuleEngine.FromPredicateAsync<string>(
    async name => { await Task.Yield(); return !taken.Contains(name); },
    name => Error.Conflict("Name.Taken", $"'{name}' is already taken."));

IRuleBase<string> nameRules = new IRuleBase<string>[]
{
    RuleEngine.FromPredicate<string>(s => s.Length <= 20, Error.Validation("Name.TooLong", "Use at most 20 characters.")),
    notEmpty,
    unique,
    new NotReservedRule(),
}.And();

foreach (string name in new[] { "ada", "admin", "" })
{
    Result result = await RuleEngine.EvaluateAsync(nameRules, name);
    Console.WriteLine($"'{name}': {(result.IsSuccess ? "ok" : result.FirstError.Code)}");
}

internal sealed class NotReservedRule : IAsyncRule<string>
{
    public async ValueTask<Result> EvaluateAsync(string context, CancellationToken cancellationToken = default)
    {
        await Task.Delay(1, cancellationToken);
        return context == "system" ? Error.Conflict("Name.Reserved", "Name is reserved.") : Result.Success();
    }
}
```

- `EvaluateAsync` takes the same arguments as `Evaluate` and returns `ValueTask<Result>` or `ValueTask<Result<T>>`. Results, short-circuiting and error order match `Evaluate`.
- Children of a composite run one at a time, in order. A tree of sync rules completes synchronously.
- `Evaluate` also runs async rules, but blocks the thread until they finish. That can deadlock under a `SynchronizationContext`. Use `EvaluateAsync` for any tree with an async rule.
- Cancelling the token throws `OperationCanceledException` from `EvaluateAsync`. It is not turned into an error. The token is checked before each rule, but a running rule is awaited until it returns, so rules should observe the token.

## Exceptions

A rule that throws does not crash the evaluation. The engine catches the exception and returns `Error.Exception` with the code `RuleEngine.Evaluate.<RuleType>` (for example `RuleEngine.Evaluate.SimpleRule` or `RuleEngine.Evaluate.AndRule`) and type `ErrorType.Unexpected`.

```csharp
Result thrown = RuleEngine.Evaluate((Applicant a) => throw new InvalidOperationException("boom"), applicant);
// thrown.FirstError.Code == "RuleEngine.Evaluate.SimpleRule", Type == ErrorType.Unexpected
```

## Empty arrays

`And`, `Or` and `Linear` over an empty array fail with the validation error `EMPTY_RULE_ARRAY`. They do not throw.

## Custom composite rules

The building blocks are public interfaces, so you can write your own composite nodes. `IRuleBase<TContext>` is the marker every rule implements.

| Interface | `Evaluate` acts as | Then the engine runs |
|---|---|---|
| `IRule<T>` / `IAsyncRule<T>` | the rule | nothing |
| `ILinearRule<T>` / `ILinearAsyncRule<T>` | the first step | `Next` on success |
| `IConditionalRule<T>` / `IConditionalAsyncRule<T>` | the condition | `Success` or `Failure`; a `null` branch returns the condition's result |
| `IAndRule<T>` / `IAndAsyncRule<T>` | a gate; a failure is returned as is | every item in `Rules` with And semantics |
| `IOrRule<T>` / `IOrAsyncRule<T>` | a gate; a failure is returned as is | every item in `Rules` with Or semantics |

Each interface also has a `<TContext, TResult>` form.

```csharp
public sealed class HasNameThen(IRuleBase<Applicant> next) : ILinearRule<Applicant>
{
    public IRuleBase<Applicant>? Next { get; } = next;

    public Result Evaluate(Applicant context, CancellationToken cancellationToken = default) =>
        string.IsNullOrWhiteSpace(context.Name) ? Error.Validation("Name.Empty", "Name is required.") : Result.Success();
}
```

Run custom composites through `RuleEngine.Evaluate` or `EvaluateAsync`. Calling `rule.Evaluate(ctx)` yourself runs only the gate or first step.

A class that implements only `IRuleBase<T>` and none of the interfaces above is not evaluated. The engine returns an `ErrorType.NotFound` error with the code `RuleEngine.Evaluate.<ClassName>`.

Never return `default(Result)` or `default(Result<T>)` from a rule as a success. In 9.0 a `default` result is a failure with the `Result.Default` error. Return `Result.Success()` or a value.
