- **AOT publish**: `dotnet publish -c Release -r linux-x64 -p:TreatWarningsAsErrors=false -p:TrimmerSingleWarn=false` from a clean obj; every sample sets `PublishAot=true` in its csproj (as a global `-p` it would also reach the CSE generator project references and fail them with NETSDK1207).
  TreatWarningsAsErrors=false is passed on the command line only; nothing is suppressed in the projects.
  TrimmerSingleWarn=false makes ILC list each warning with its member instead of one IL2104/IL3053 line per package assembly, so counts are higher than a default publish shows.
- **IL warnings**: distinct `warning IL` lines. *analyzer* = Roslyn trim/AOT analyzers at compile time (call sites in the sample); *ILC* = whole-program trim/AOT analysis during native compilation (inside libraries).
- **Startup**: ms from process start to the first 200 on `GET /users/1`, median of 5 runs after one discarded warm-up run; polled every ~2 ms over a raw socket. JIT = framework-dependent publish with PublishAot=false (so no Request Delegate Generator).
- **Route check** (warm-up run): POST valid -> 201, POST invalid -> 400, DELETE -> 204. Validation engines differ: DataAnnotations + `AddValidation()` for Plain/CSE, FluentValidation for Carter and FastEndpoints.
- **JSON contexts**: Native AOT turns reflection-based JSON off. Plain, CSE and Carter list `HttpValidationProblemDetails` in their `JsonSerializerContext` because the 400 body is written with the app JSON options; without it invalid input returns 500. The FastEndpoints samples list `ErrorResponse` because a per-endpoint `SerializerContext<T>()` replaces the default resolver for that endpoint, failure body included.
- **FastEndpoints**: JSON uses the documented manual per-endpoint context (model-binding#source-generators) rather than `GenerateSerializerContexts`, which installs a local dotnet tool from the network on every fresh build. Request DTOs use `{ get; set; }`, because FastEndpoints.Generator emits no setter for init-only properties and the binder would fall back to runtime-compiled setters. FastEndpointsSourceGenAot registers the generated reflection data (configuration-settings#source-generated-reflection).
- **Carter** documents no Native AOT approach, so CarterAot uses the plain minimal-API `JsonSerializerContext`; it gets an `Assembly[]` catalog because a single `Assembly` binds to the constructor that walks deps.json. Invalid input answers 400 (the Carter sample answers 422) so every variant returns the same status.
- Startup numbers are machine-noise sensitive; regenerate on a quiet machine before quoting them.
